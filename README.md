# @michaelthomasjach/liseuse-dashboard-kit

Bibliothèque de composants React pour construire des tableaux de bord — domotique façon liseuse e-ink (BOOX, Kindle…) ou tablette, et applications finance (graphiques D3 interactifs, formulaires, layouts, pages). Chaque composant supporte nativement :

- **Palette** — `eink` (monochrome, hairlines, sans ombre ni dégradé) ou `color` (tablette couleur, accents pastel).
- **Surface** — `light` (Clair) ou `dark` (Sombre).
- **Typo** — `space-grotesk`, `manrope`, ou `sora`.

Les quatre combinaisons palette × surface sont pilotées par variables CSS ; aucune classe conditionnelle à gérer côté consommateur. Les deux palettes partagent la **même géométrie** — coins carrés partout (`--lq-radius-*` vaut `0px` dans les deux cas), `color` n'est qu'une variante *colorée* du même langage visuel qu'`eink`, pas un style différent. Les couleurs de `color` sont volontairement **pastel/dusty** (désaturées) plutôt que des teintes UI-kit brutes, pour rester cohérentes avec la sobriété d'`eink`.

## Installation

Le package est publié sur **GitHub Packages**, pas sur npmjs.org. Il faut donc router le scope `@michaelthomasjach` vers le registre GitHub.

Dans le projet consommateur, ajoute un fichier `.npmrc` :

```
@michaelthomasjach:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

`GITHUB_TOKEN` doit être un token GitHub avec le scope `read:packages` (variable d'env locale, ou secret CI).

```bash
npm install @michaelthomasjach/liseuse-dashboard-kit d3
```

`react`, `react-dom` et `d3` sont des **peerDependencies** (non bundlées) — installe-les dans le projet consommateur si ce n'est pas déjà fait. `d3` n'est nécessaire que si tu utilises les graphiques (`components/charts`) ; le reste de la lib fonctionne sans.

## Usage

```tsx
import {
  LqThemeProvider,
  ClockWidget,
  WeatherWidget,
  ShuttersWidget,
  DashboardGrid,
  DashboardGridItem,
} from "@michaelthomasjach/liseuse-dashboard-kit";
import "@michaelthomasjach/liseuse-dashboard-kit/style.css";

function App() {
  return (
    <LqThemeProvider palette="eink" surface="dark" font="sora">
      <DashboardGrid columns="1.1fr 1fr 1fr">
        <DashboardGridItem>
          <ClockWidget time="20:14" date="samedi 7 juin" />
          <WeatherWidget icon={<SunIcon />} temperature="16" condition="Partiellement nuageux" />
        </DashboardGridItem>
        <DashboardGridItem>
          <ShuttersWidget
            meta="2 ouverts"
            shutters={[
              { id: "salon", label: "Salon TV", on: true, level: 51, statusText: "51 %", onToggle: (on) => {} },
            ]}
          />
        </DashboardGridItem>
      </DashboardGrid>
    </LqThemeProvider>
  );
}
```

Un seul `<LqThemeProvider>` suffit pour toute l'app ; on peut aussi en imbriquer plusieurs pour prévisualiser deux modes côte à côte.

```tsx
import { useLqTheme } from "@michaelthomasjach/liseuse-dashboard-kit";

```

### Polices

La lib ne bundle pas les fonts (pour rester légère et éviter les conflits de licence) : elle expose seulement les piles de police. Charge Space Grotesk / Manrope / Sora depuis Google Fonts (ou en self-hosted) dans l'app consommatrice :

```html
<link
  href="https://fonts.googleapis.com/css2?family=Space+Grotesk:wght@400;500;600;700&family=Manrope:wght@400;500;600;700;800&family=Sora:wght@400;500;600;700&display=swap"
  rel="stylesheet"
/>
```

### Scrollbars

Toute zone scrollable sous `.lq-root` reçoit automatiquement un ascenseur fin et discret (`scrollbar-width`/`scrollbar-color` sur Firefox, `::-webkit-scrollbar` ailleurs), avec une opacité faible au repos qui augmente au survol **et** pendant un scroll actif (classe `.lq-scrolling`, posée/retirée par un unique listener `scroll` global — voir `theme/scrollActivity.ts`, importé une seule fois par `LqThemeProvider` quel que soit le nombre d'instances montées).

## Composants

**Thème**
- `LqThemeProvider`, `useLqTheme`

**Icônes**
- Set d'icônes SVG (`SunIcon`, `MoonIcon`, `PartlyCloudyIcon`, `CloudRainIcon`, `WindIcon`, `CloudIcon`, etc.) — voir la story "Foundations/Animated Icons"
- Certaines icônes météo acceptent une prop `animated` (boucle idle discrète) : soleil qui tourne lentement, lune qui respire (échelle/opacité), petit soleil du "partiellement nuageux" qui tourne (le nuage reste fixe), gouttes de pluie qui tombent en cascade décalée, vent qui ondule légèrement. Désactivé automatiquement sous la palette e-ink et `prefers-reduced-motion` (comme les autres animations décoratives)

**Primitives** — brique de base réutilisable dans n'importe quel écran
- `Panel`, `PanelRow` — carte de section avec titre/meta et lignes label/valeur
- `Toggle` — interrupteur on/off
- `LevelGauge` — jauge segmentée (niveau volet, luminosité, volume, batterie…)
- `Button`, `IconButton` — actions discrètes / boutons carrés à icône
- `ColorSwatchButton` — case à cocher couleur (dégradée en gris sous la palette e-ink)
- `Modal` — panneau de détail centré ; `size="fullscreen"` pour une variante qui occupe la quasi-totalité de l'écran (96vw × 92vh) au lieu de la petite boîte centrée par défaut. Le padding vit sur un wrapper interne (`.lq-modal__inner`), pas sur `.lq-modal` lui-même : c'est `.lq-modal` qui porte `overflow-y: auto`, et une scrollbar sur une boîte *déjà paddée* mange dans le padding de ce côté-là au lieu de s'afficher à côté — le padding gauche restait entier pendant que le droit semblait disparaître. Garder `.lq-modal` sans padding fait apparaître la scrollbar au ras de sa bordure, en dehors de la boîte du wrapper, donc son padding reste symétrique que la scrollbar soit visible ou non
- `FieldGroup` — label + rangée de contrôles
- `SegmentedControl` — sélecteur exclusif (ex: le switch Palette/Surface/Typo de la maquette)
- `Tabs` — navigation par onglets, horizontale ou verticale (`orientation`)
- `Jumbotron` — bannière promo/hero (eyebrow, titre, description, actions, media ou image de fond avec `imageFilter="grayscale"`)
- `TreeView` — arbre expand/collapse récursif, avec glisser-déposer optionnel (`onMove`) pour réorganiser/reparenter — voir l'utilitaire `moveTreeNode`
- `ExpandableCard` — carte qui se déplie verticalement (animation CSS pure, pas de mesure JS)
- `TabbedCard` — carte dont le corps est découpé en onglets (`orientation="horizontal"|"vertical"`)
- `Testimonial` — carte témoignage (citation, avatar/initiales, nom, rôle, note en étoiles)
- `CodeBlock` — bloc de code monospace avec bouton copier ; pas de coloration syntaxique (pas de dépendance lourde), numéros de ligne optionnels
- `Heading`, `Text` — typographie du système (h1-h6, tailles xs→xl, graisses, variante atténuée) — voir la story "Foundations/Typography"

**Widgets** — composants métier prêts à brancher sur tes données
- `ClockWidget` — heure/date + ligne de présence
- `WeatherWidget` — météo courante, alerte, prévision multi-jours
- `DayTimelineWidget` — jalons de la journée (Matin, Dodo, Départ…)
- `MusicPlayerWidget` — lecteur audio compact
- `MetricListWidget` — liste label/valeur générique (températures des pièces…)
- `ShuttersWidget` — liste de volets (toggle + jauge d'ouverture)
- `LightsWidget` + `LightDetailModal` — liste de lumières + détail (allumage, température, couleur)
- `EnergyWidget` — métriques énergie mixtes (valeur simple ou jauge, ex. batterie)
- `DashboardGrid`, `DashboardGridItem` — grille CSS pour composer la page

Chaque widget est piloté par des props (pas de fetch ni d'état interne caché) : à toi de brancher tes propres données/API.

**Charts** — SVG piloté par React, D3 pour les maths (scales/zoom/shapes) uniquement ; remplissent 100% de la largeur du conteneur par défaut, avec une bordure (`--lq-color-border-subtle`) qui englobe tout le composant (graphe, axes, en-tête, barre d'outils) pour bien le délimiter dans une page. Exception : `CandlestickChart` dessine les bougies/volume/crosshair/lignes de dessin sur un `<canvas>` superposé (un seul élément quel que soit le nombre de bougies, au lieu d'un nœud SVG par bougie) pour de meilleures performances avec de gros historiques ; les axes, la barre d'outils et les zones interactives (zoom/pan/drag d'axe/poignées de dessin) restent en SVG par-dessus, donc l'API et les interactions ne changent pas. Le canvas relit les tokens CSS (couleurs) à chaque redessin et se resynchronise automatiquement au changement de thème. Tous les graphiques cartésiens (`LineAreaChart`, `BarChart`, `CandlestickChart`, `DeltaChart`) partagent le même moteur de zoom/pan que le candlestick : molette/pincement + glisser dans le graphe pour zoomer/naviguer sur l'axe principal, glisser **ou molette** sur l'axe vertical pour rescale cet axe, glisser **ou molette** sur l'axe horizontal pour rescale celui-là — indépendamment l'un de l'autre, **double-clic sur un axe pour réinitialiser uniquement le zoom de cet axe**. `BarChart`/`DeltaChart` traitent leur axe catégoriel comme un axe continu (position par index) pour pouvoir zoomer/naviguer parmi de nombreuses barres/étapes, avec un nombre d'étiquettes affichées qui s'adapte au niveau de zoom. Les tracés sont clippés à la zone du graphe (jamais par-dessus les axes). `ChartAxis` (partagée par tous les graphiques) trace sa ligne de domaine et ses graduations dans la même couleur/épaisseur que la bordure du graphe (`--lq-color-border-subtle`, 1px) pour qu'elle se lise comme faisant partie de la même délimitation, et masque automatiquement toute étiquette dont le texte (centré sur sa graduation) déborderait de la plage valide de l'axe — le tick lui-même peut rester dans les clous tout en laissant son étiquette dépasser, typiquement la première/dernière graduation, pile sur le bord du domaine ; ce masquage bascule `visibility` (pas `display: none`) pour qu'une étiquette masquée reste mesurable et puisse redevenir visible plus tard — `display: none` donnait un `getBoundingClientRect()` toujours à zéro, donc une étiquette une fois masquée (typiquement en glissant/zoomant l'axe) restait coincée masquée indéfiniment, y compris une fois qu'elle aurait légitimement eu la place de s'afficher. Bouton plein écran dans la barre d'outils (`fullscreenToggle`, overlay CSS `position:fixed` plein viewport — fonctionne partout, y compris dans un iframe sandboxé comme celui de Storybook, contrairement à l'API Fullscreen native) : `z-index: 500`, en dessous de `Modal`/`Popover`/`Notification` (portalés sur `document.body`, donc simples frères de l'overlay dans le DOM — ils ne passent au-dessus que si leur propre `z-index` l'emporte) pour qu'une modale ou un menu déroulant ouvert pendant le plein écran reste cliquable au lieu de se peindre derrière ; la bordure du plein écran utilise `--lq-color-border` (pas `-subtle`) puisqu'il n'y a plus de page autour pour lui donner du contraste, contrairement au mode normal ; l'espace autour du graphe en plein écran vient d'un `inset` (le `.lq-chart--fullscreen` est décalé du bord du viewport) plutôt que d'un `padding` sur cette même boîte — combiner `position: fixed` et `padding` sur l'élément qui porte aussi la bordure cassait cette dernière, `inset` donne le même espace visuel sans jamais mélanger `padding` dans la boîte d'un élément fixe. Zoom désactivable via `zoomable={false}` sur chacun.
- `LineAreaChart` — courbe/aire multi-séries, zoom + pan + rescale par axe, tooltip avec crosshair, légende cliquable (masquer une série)
- `BarChart` — barres verticales/horizontales, zoom + pan + rescale par axe (axe catégoriel en index continu), tri par valeur (`colorByValue` pour vert/rouge automatique)
- `CandlestickChart` — chandeliers OHLC + volume, zoom + pan + rescale par axe ; convention creux/plein en palette e-ink (le monochrome ne peut pas coder la hausse/baisse par la teinte). Tient à l'aise sur des milliers de bougies grâce au rendu canvas (voir plus haut) ; un séparateur marque la frontière entre le tracé des prix et celui du volume, flush contre le tracé des prix (aucune marge de respiration au-dessus), sur toute la largeur du composant (y compris à travers la colonne des étiquettes de l'axe des prix, pas juste le tracé lui-même) — l'échelle du volume réserve 10% de marge au-dessus de sa plus haute barre pour garder un petit vide visuel sous ce trait ; survoler le tracé du volume affiche sa valeur exacte en badge ancré sur son propre axe, comme pour le prix ; le tout masquable via `showVolume={false}` ; le tracé des prix et celui du volume sont chacun clippés à leur propre rectangle sur le canvas, donc glisser/zoomer l'axe des prix ne peut jamais faire déborder visuellement les bougies (ni les lignes de dessin) dans la zone du volume — seul le crosshair vertical traverse volontairement les deux. La colonne d'outils et la barre d'en-tête ont un fond opaque et un `z-index: 1000` (le badge de valeur sur l'axe Y : `999`) pour ne jamais laisser transparaître ou déborder ce qui est dessiné sur le canvas en dessous. le zoom horizontal va jusqu'à n'afficher qu'une seule bougie, quelle que soit la taille du jeu de données — chaque bougie occupe jusqu'à 80% de l'espace réellement disponible à ce niveau de zoom (donc ~80% de la largeur du graphe s'il n'y en a qu'une seule visible), sans jamais se chevaucher (pas de largeur minimale forcée) ni laisser d'espace vide sur les bords (la première/dernière bougie a le même "slot" que les autres, pas la moitié coupée pile sur le bord du graphe). Aucune marge de respiration superflue : le tracé est délimité exactement par les bordures qui l'entourent (bordure basse de l'en-tête en haut, bordure de la colonne d'outils à gauche) plutôt que de laisser un espace vide entre elles et les bougies — la marge gauche par défaut est nulle (`0`, pas juste petite) pour que le graphe touche la bordure gauche du composant quand `drawingTools` est désactivé, elle ne réapparaît que pour réserver la place de la colonne d'outils quand celle-ci est affichée. Glisser dans le graphe pan simultanément les deux axes (utile pour retrouver des bougies sorties de l'écran après un rescale vertical). Pas d'infobulle flottante : le prix et la date exacts sous le curseur s'affichent directement en badge ancré à l'axe (sans jamais déborder par-dessus les bougies, quelle que soit la largeur du texte). Un petit bouton **+** permet d'ajouter une ligne de prix horizontale, une ligne de volume horizontale ou une ligne de date verticale : ceux du prix et du volume sont englobés par leur badge respectif (dont le fond déborde légèrement sur le graphe pour leur faire de la place, léger surlignage juste derrière le bouton au survol, sans padding propre — le bouton occupe toute la hauteur du badge, comme un vrai segment de celui-ci) ; celui de la date est un carré séparé, même couleur de fond que les badges, ancré dans l'axe du crosshair (à l'abscisse de la date survolée) et décalé du bord bas du graphe pour ne jamais toucher visuellement le badge de date en dessous — ce badge-là est hors de la zone interactive du graphe, et un bouton qui y aurait vécu aurait été inatteignable : en sortir du graphe pour l'atteindre aurait déclenché la perte du survol (et donc sa disparition) avant que le clic n'arrive. Une fois placée, une ligne **horizontale**/**horizontale à partir d'une date** affiche en permanence son propre prix (ou volume) sur l'axe Y, même badge visuel que celui du survol ; une **horizontale à partir d'une date** affiche en plus sa date de départ sur l'axe X, mais seulement tant que sa ligne est survolée — contrairement au badge de prix, qui reste affiché en continu. Ces trois lignes sont des `TrendLineDrawing` avec un `lineType` (`"horizontal"` ou `"vertical"`, voir aussi `"ray"`/`"extended"`/`"channel"`/`"disjointChannel"`/`"fibonacci"`/`"fibonacciExtension"`/`"elliottImpulse"`/`"elliottCorrection"` plus bas) qui les contraint à un seul axe : une ligne horizontale ne peut être déplacée que verticalement (son prix/volume change, sa portée reste tout l'historique) via un unique cercle de poignée positionné au 1/4 du bord droit ; une ligne verticale ne peut être déplacée qu'horizontalement (sa date change, sa portée reste toute la hauteur — prix **et** volume, pas seulement la zone des prix) via un unique cercle positionné au 1/4 du bord haut — contrairement aux deux poignées indépendantes d'une ligne de tendance classique. Éditables/déplaçables/supprimables comme n'importe quelle ligne dessinée à la main (la modale d'édition adapte ses champs en conséquence : un seul prix/volume ou une seule date, pas deux extrémités séparées). **Axe des prix à droite** ; une vraie barre d'en-tête (pas flottante) porte le sélecteur d'intervalle optionnel (`timeframes`/`timeframe`/`onTimeframeChange` — le composant affiche juste le choix, à l'app de rééchantillonner `data`), un sélecteur de **mode d'affichage** (icône du mode courant, ouvre un menu des six modes — `ChartDisplayMode`, `defaultChartDisplayMode`/`onChartDisplayModeChange`, non contrôlé comme `drawings`/`indicators`) et les boutons zoom/plein écran. Les six modes : `"candle"` (bougies, défaut), `"line"` (ligne de clôture avec un léger remplissage en dessous), `"heikinAshi"` (OHLC transformé selon la formule standard — `open` = moyenne open/close de la bougie HA précédente, `close` = moyenne des 4 valeurs OHLC réelles, `high`/`low` = étendus si besoin pour englober `open`/`close` — réindexé 1:1 sur les mêmes dates que `data`, donc zoom/pan/indicateurs/dessins n'ont besoin d'aucun changement), `"renko"` (briques de taille fixe basée sur l'ATR — `renkoAtrPeriod`, défaut 14, recalculé sur tout le jeu de données — une nouvelle brique par tranche de mouvement de clôture franchie, plusieurs briques d'un coup si le mouvement est assez grand ; se renverse sur une seule brique de sens opposé, simplification courante plutôt que la règle stricte à 2 briques), `"lineBreak"` ("Three Line Break" : une nouvelle ligne prolonge la tendance sur un nouveau plus haut/bas, un renversement seulement si la clôture dépasse l'extrême des 3 dernières lignes — sinon aucune nouvelle ligne, contrairement au Renko où chaque bougie est au moins testée) et `"tpo"` (Time Price Opportunities : garde les bougies classiques et ajoute par-dessus un histogramme de distribution des prix — combien de bougies touchent chaque niveau, sur la plage actuellement visible, recalculé au pan/zoom comme `YAutoScaling` — ancré à droite du graphe, plus trois lignes pointillées **VAH**/**POC**/**VAL** : POC = le niveau le plus fréquenté, la zone de valeur s'étend depuis lui vers le voisin le plus dense jusqu'à couvrir 70% du total, VAH/VAL en marquent les bords). Renko et Line Break n'ont pas d'index propre à eux : chaque brique est positionnée sur l'échelle par index existante, occupant exactement la plage de bougies source qu'il a fallu pour la former (`startIndex`/`endIndex`) plutôt qu'une largeur uniforme sur un axe dédié — ça les garde synchronisées avec le zoom/pan/volume/indicateurs sans toucher au reste du fichier, au prix d'une largeur de brique irrégulière. Outils de dessin optionnels (`drawingTools`) : une vraie colonne verticale réservée **à gauche** du graphe (pas des boutons superposés — l'axe/le tracé ne dessinent jamais dessous, et elle reste visible en plein écran), dont la bordure délimite exactement le début du tracé. Les outils sont groupés en **catégories** empilées verticalement dans la colonne (`DRAWING_TOOL_CATEGORIES`) — "Lignes" (tendance, étendue, canal, canal disjoint, horizontale, horizontale à partir d'une date, verticale), "Fibonacci" (retracement, extension) et "Vagues d'Elliott" (impulsive, correctrice) — chacune avec son propre bouton (icône + chevron + menu déroulant), indépendante des autres. Chaque bouton représente le dernier outil choisi *dans sa propre catégorie* (par défaut le premier de la liste), avec un chevron dans son coin invisible tant que ni le bouton ni le chevron ne sont survolés/focus — cliquer le chevron ouvre le menu de cette catégorie. **Choisir une entrée dans un menu l'active immédiatement** (prêt à dessiner dès ce clic, pas besoin de recliquer le bouton) ; cliquer le bouton d'une catégorie ensuite (re)bascule ce même outil actif/inactif, comme n'importe quel autre déclenchement d'outil. "Ligne de tendance"/"Ligne étendue"/"Retracement de Fibonacci" — 1er clic = point de départ (la ligne suit ensuite le curseur), 2ème clic = point d'arrivée ; Échap ou re-clic sur l'outil annule le point en cours et désélectionne l'outil ; un clic en dehors du graphe ne fait rien. "Canal" étend ce flux à 3 clics : les deux premiers fixent la première ligne exactement comme "Ligne étendue", le 3ème fixe l'écart (`channelOffset`, un delta de prix constant, pas une vraie distance perpendiculaire — même simplification que la plupart des plateformes de trading pour cet outil) d'une seconde ligne parallèle — sa propre poignée (au milieu de cette 2ème ligne) ne bouge que verticalement, les deux poignées de la 1ère ligne restent indépendantes comme sur une ligne de tendance classique. "Canal disjoint" (`lineType: "disjointChannel"`) suit le même flux à 3 clics que "Canal" (2 points pour la ligne 1, un 3ème pour l'écart), mais son 4ème point n'est pas calculé en parallèle : la ligne 2 est le **miroir** de la ligne 1 par rapport au point 2 (symétrie centrale, donc de pente opposée) puis décalée de l'écart du 3ème clic — les 4 points obtenus (comme pour tout outil multi-points) restent ensuite indépendamment déplaçables à la main pour ajuster l'angle de la ligne 2 sans toucher à la ligne 1. Les trois outils à un seul point n'ont besoin que d'un seul clic sur le graphe — "Ligne horizontale"/"Ligne horizontale à partir d'une date" basculent automatiquement entre prix et volume selon la zone cliquée, "Ligne verticale" (comme celle du bouton **+** de l'axe des dates) couvre toute la hauteur. "Ligne étendue" garde les deux mêmes points qu'une ligne de tendance (ce sont eux qui restent déplaçables) mais le tracé continue au-delà, jusqu'aux bords gauche/droit du graphe, plutôt que de s'arrêter pile dessus. "Retracement de Fibonacci" utilise lui aussi ces deux mêmes points (0% à "Prix début", 100% à "Prix fin", pas de champ dédié) : le ratio entre les deux est découpé selon les niveaux standards (0, 23.6, 38.2, 50, 61.8, 78.6, 100%, `FIBONACCI_LEVELS`, non configurables) et chacun est tracé en segment horizontal sur toute la portée x1/x2, étiqueté ratio + prix — en plus de la diagonale x1/y1–x2/y2 elle-même, dessinée comme pour une ligne de tendance classique. "Extension de Fibonacci" prend 3 points (A, B, C — mêmes 2 premiers clics que "Canal", suivis d'un 3ème) et projette les niveaux d'extension standards (`FIBONACCI_EXTENSION_LEVELS` : 0, 38.2, 61.8, 100, 138.2, 161.8, 200, 261.8%) à partir de C selon l'ampleur du mouvement A→B — la formule "trend-based extension" conventionnelle — chaque niveau en segment horizontal entre B et C, étiqueté ratio + prix, en plus des segments A-B et B-C eux-mêmes. "Vague d'Elliott (impulsive)" et "(correctrice)" collectent respectivement 6 points (labellisés 0-1-2-3-4-5) et 4 points (0-A-B-C) formant une ligne brisée connectée, chaque sommet étiqueté sur le graphe — au-delà des deux premiers points (mêmes champs "Début"/"Fin" que les autres outils), la modale d'édition affiche un champ date/prix supplémentaire par point restant. Tous les outils à plus de deux points (canal excepté, qui garde son propre flux dédié) partagent la même collecte générique point par point (`extraPoints` sur `TrendLineDrawing`, au-delà de `x1`/`y1`/`x2`/`y2`) et les mêmes poignées de glisser génériques (une par point, plus celle de canal pour son écart) — glisser le corps d'un dessin déplace tous ses points ensemble, quel que soit leur nombre. Les lignes sont ancrées en coordonnées date/prix (`onDrawingsChange`) donc elles suivent le zoom/déplacement ; survoler une ligne dessinée affiche ses poignées (à glisser pour la redéfinir — une seule pour une ligne horizontale/verticale, contrainte à son axe ; deux indépendantes pour une ligne de tendance), glisser directement sur la ligne la déplace entièrement, et **double-clic dessus ouvre une modale d'édition**, organisée en trois onglets (`Tabs`) — **Coordonnées** (dates/prix, comme avant), **Texte** (le libellé, une case "aligner le texte avec la ligne" qui fait pivoter le texte le long du segment via `Math.atan2`, une taille en px, gras/italique, alignement vertical haut/centre/bas et horizontal gauche/centre/droite — deux `Select` combinés en position d'ancrage le long du segment ou en décalage perpendiculaire à celui-ci — et une couleur de fond optionnelle avec un lien pour la retirer) et **Style** (épaisseur, couleur, un style de trait — continu/tirets/pointillés/tiret-point, `lineStyle`, remplace l'ancienne case "Pointillés" tout en restant compatible avec les dessins existants qui n'avaient que `dashed`, et une extension — aucune/droite/gauche/des deux côtés, `extend`, uniquement pour une ligne à deux points classique ou "étendue" ; les autres types de ligne ont leur propre géométrie fixe et ignorent ce champ) — plus la suppression, en pied de page. Les champs de prix (`NumberField`) sont arrondis à 4 décimales maximum dès la saisie, quel que soit l'onglet ou le nombre de points de l'outil. ses deux boutons de pied de page (`min-width: 0` chacun) se partagent la largeur sans jamais déborder de la modale, même si leur contenu ne le permettrait pas naturellement à `flex: 1` seul (le comportement par défaut d'un flex item est de ne jamais rétrécir sous la largeur de son propre contenu). Indicateurs techniques optionnels (`showIndicators`) : un bouton dans l'en-tête (à côté du sélecteur d'intervalle) ouvre une modale listant les indicateurs disponibles (SMA, EMA, WMA, VWAP, bandes de Bollinger, RSI, CHOP, MACD — `Indicator`/`IndicatorKind` exportés, détails plus bas) ; cliquer une entrée l'ajoute au graphe (période par défaut affichée, la modale reste ouverte pour en ajouter plusieurs). Chaque indicateur actif apparaît en haut à gauche du graphe (liste `defaultIndicators`/`onIndicatorsChange`, contrôlable comme `drawings`) dans sa propre couleur (cyclée depuis une petite palette, sauf `color` explicite) ; survoler son étiquette fait apparaître une roue crantée qui ouvre ses paramètres (période, couleur) dans une modale, **double-clic sur l'étiquette** fait la même chose directement — juste au-dessus, dans ce même coin, un nouveau bandeau affiche `symbol` (le nom de l'instrument, optionnel) suivi du mode d'affichage courant ; **double-clic dessus** ouvre la modale **"Paramètres du graphique"** (couleurs des bougies haussières/baissières — remplace `--lq-color-up`/`--lq-color-down` juste pour ce graphe, un bouton réinitialise aux couleurs du thème —, la case **rescale automatique de l'axe des prix au zoom**, qui pilote désormais `YAutoScaling` en direct au lieu d'être un simple prop figé au montage — `onYAutoScalingChange` remonte le changement —, et une case à cocher par type d'évènement présent dans `events`, si `events` est fourni). Juste à côté du nom : l'**OHLC** et la variation en % de la bougie actuellement survolée (la plus récente par défaut, tant que rien n'est survolé), la variation calculée par rapport à la clôture de la bougie précédente, pas à l'ouverture de la bougie elle-même. `events?: ChartEvent[]` affiche une petite bulle par évènement (résultats, dividendes, mises à jour…) en bas du tracé des prix, positionnée sur le même axe des dates par index que tout le reste (donc elle suit le zoom/pan) avec un connecteur pointillé vers l'axe ; `ChartEvent.kind` est une chaîne libre définie par l'app (pas une énumération fixée par le composant) qui regroupe les évènements pour la case à cocher de la modale de paramètres et pour la couleur par défaut (cyclée par type, sauf `color` explicite) ; le glyphe affiché dans la bulle est la première lettre de `kind` en majuscule, sauf si `symbol` (1-2 caractères) est fourni ; survoler une bulle affiche sa date et son `label` en infobulle native. Superposé au tracé des prix (jamais au volume), calculé sur les clôtures et rendu sur le même canvas que les bougies, donc soumis au même clip/fenêtrage que les prix (jamais visible dans la zone du volume, recalculé uniquement quand les données ou la liste d'indicateurs changent — pas à chaque frame de zoom/pan, pour rester fluide sur de gros historiques). `initialVisibleCandles` (défaut **500**) : zoom/pan initial appliqué une seule fois au montage (pas à chaque redimensionnement) pour n'afficher que les N dernières bougies plutôt que tout l'historique dézoomé — passe une valeur ≥ `data.length` (ou 0) pour désactiver et retrouver l'ancien comportement (tout l'historique visible dès l'ouverture). `YAutoScaling` (défaut `false`) : l'axe des prix se recadre en continu sur le min/max des bougies **actuellement visibles** sur l'axe des dates (recalculé à chaque pan/zoom horizontal, sans relancer le calcul sur les changements de survol/état sans rapport) au lieu d'une échelle figée sur tout le jeu de données — jusqu'à ce que l'utilisateur zoome/glisse **manuellement** l'axe des prix lui-même (molette/glisser sur l'axe, ou glisser verticalement dans le graphe), ce qui suspend le recadrage automatique pour ne pas écraser son réglage ; cliquer "Réinitialiser le zoom" le réactive. Implémenté sans changer l'échelle des prix elle-même (qui reste stable, basée sur tout le jeu de données) : un effet dérive plutôt le `yTransform` équivalent qui ferait correspondre le rendu à la plage visible, donc `isZoomed`/le bouton de réinitialisation ne restent pas allumés en permanence à cause de ce recadrage automatique — seul un ajustement manuel les déclenche. **Axe des dates positionné par index, pas par le temps réel écoulé** : chaque bougie occupe un slot de largeur fixe (même principe que l'axe catégoriel de `BarChart`/`DeltaChart`), au lieu d'une position proportionnelle à sa date calendaire — une vraie échelle temporelle laissait un vide visuel chaque week-end/jour férié (le vendredi et le lundi suivant s'écartaient proportionnellement au temps écoulé entre les deux), regroupant les bougies en paquets séparés par des trous plutôt que collées les unes aux autres comme sur une plateforme de trading. Les coordonnées `x`/`x1`/`x2` exposées publiquement (`TrendLineDrawing`, `defaultDrawings`…) restent des `Date` normales — la conversion index ↔ date se fait en interne à l'affichage/l'interaction, donc l'API ne change pas. **Décalage vers le "passé"/"futur"** : glisser au-delà de la première ou de la dernière bougie révèle un espace vide de ce côté au lieu de rester bloqué pile sur le bord des données, plafonné à 50% de la largeur *actuellement visible* de chaque côté — pas un nombre fixe de bougies vides, qui paraîtrait énorme très zoomé et négligeable dézoomé. Implémenté via une fonction `constrain` personnalisée passée au comportement `d3.zoom()` sous-jacent (`useD3Zoom`) plutôt que son `translateExtent` par défaut, qui ne peut exprimer qu'une marge fixe en unités du monde (donc une fraction de la fenêtre visible qui varie avec le zoom) — jamais montré par défaut à l'ouverture, et la largeur des bougies reste calculée sur la fenêtre zoomée entière (slots vides compris) pour ne pas changer pendant qu'on navigue dedans. La légende des indicateurs (image ci-dessus) n'a plus de bordure autour de chaque entrée — seul un trait `1px solid var(--lq-color-border-subtle)` sépare les entrées empilées entre elles (dernière entrée exclue), même logique que les autres séparateurs du graphe ; survoler une entrée fait apparaître trois icônes (au lieu de la seule roue crantée avant) : œil (masquer/afficher — l'indicateur reste dans la liste mais son tracé disparaît du graphe, son icône devient barrée et son étiquette passe à 50% d'opacité), corbeille (suppression directe, sans passer par la modale de paramètres) et roue crantée (paramètres, inchangée). Les lignes canvas censées prolonger une bordure CSS (séparateur prix/volume, prolongement de l'axe des dates dans la colonne de l'axe des prix) sont alignées sur la grille de pixels (`Math.round(v) + 0.5`) pour rester nettes au lieu de s'étaler sur deux rangées de pixels avec de l'anti-aliasing (ce qui les faisait paraître plus épaisses et d'une teinte légèrement différente de la bordure du graphe) — le segment SVG qui prolonge chacune applique le même arrondi pour rester pixel-aligné avec son homologue dessiné sur le canvas. `width`/`height` (px) : taille fixe explicite au lieu de la largeur à 100% du conteneur / hauteur 380 par défaut (les deux ignorés en plein écran, qui remplit toujours le viewport) — seul `CandlestickChart` expose `width` pour l'instant, les autres graphiques restent 100%-large par défaut. `useChartDimensions` (partagé par tous les graphiques) re-mesure désormais son wrapper de façon synchrone (`useLayoutEffect`) dès qu'une largeur/hauteur fixe est ajoutée, retirée ou changée — en plus du `ResizeObserver` habituel, dont le callback est asynchrone : en ne comptant que sur lui, sortir du plein écran laissait les axes (mutés en place par d3, contrairement au canvas qui se redessine entièrement à chaque rendu) dessinés sur les dimensions plein écran pendant un ou deux rendus, débordant visiblement du graphe redevenu plus petit. Indicateurs techniques : en plus de SMA/EMA/WMA (calculés en interne), **VWAP** et **bandes de Bollinger** sont calculés via la librairie npm [`technicalindicators`](https://www.npmjs.com/package/technicalindicators) (tree-shakée — seuls les deux indicateurs réellement importés finissent dans le bundle) ; Bollinger expose aussi `stdDev` (défaut 2) sur `Indicator` et se dessine en bande (ligne médiane pleine, bornes upper/lower fines, remplissage translucide entre les deux) plutôt qu'une simple ligne — le draw effect distingue les deux avec un simple `typeof value === "number"`. `TrendLineDrawing` expose `dashed` (défaut `false`, éditable dans la modale) pour n'importe quel type de ligne. Nouvel outil de dessin **"ligne horizontale à partir d'une date"** ("ray", `lineType: "ray"`) dans le menu de la colonne d'outils : comme une ligne horizontale mais ancrée à la date cliquée au lieu de couvrir tout l'historique — dessinée de cette date jusqu'au bord droit du graphe seulement. Contrairement à `"horizontal"`/`"vertical"` (un seul axe modifiable via une poignée à fraction fixe), un ray garde ses deux degrés de liberté : sa poignée unique suit son ancre réelle et se glisse librement en date **et** en prix/volume à la fois, et glisser le corps de la ligne fait pareil. **Double-clic sur le graphe** réinitialise le zoom (X et Y) — sauf en survolant une ligne dessinée, où le double-clic garde son sens existant (ouvrir sa modale d'édition), le reset ne s'applique qu'au double-clic sur une zone vide du graphe. La légende des indicateurs n'a plus de fond au repos, seulement au survol/focus (même token `--lq-color-panel` que les autres badges du graphe) — avant, le fond était permanent. **Panneau volume** (même traitement prévu pour de futurs indicateurs en sous-panneau — RSI, MACD…) : son nom ("Volume") reste affiché en haut à gauche du panneau ; le survoler fait apparaître en haut à droite deux boutons — réduire (le panneau devient un simple bandeau de 40px sur toute la largeur, avec le nom à gauche et un bouton pour l'agrandir de nouveau à droite) et supprimer (masque le panneau entièrement, sans action pour le ramener depuis l'UI — comme la suppression d'un indicateur ou d'une ligne dessinée) ; état purement local au composant (pas de prop), qui vient se superposer à `showVolume` plutôt que le remplacer — `showVolume={false}` masque toujours tout, ce nouvel état ne fait qu'ajuster comment le panneau se présente une fois affiché. **RSI, CHOP et MACD** (`IndicatorKind`) ont chacun leur propre sous-panneau sous le volume, empilés dans l'ordre où ils ont été ajoutés — même en-tête que le volume (nom, réduire/agrandir, supprimer) plus une roue crantée pour leurs paramètres (période pour RSI/CHOP ; rapide/lent/signal — défaut 12/26/9 — pour MACD, `IndicatorMACD` exporté). RSI/CHOP sont bornés 0-100 par définition (lignes de référence en pointillés à 30/70 pour RSI, 38.2/61.8 pour CHOP, absent de la librairie `technicalindicators` donc calculé à la main à partir de sa définition — somme du true range sur la période, divisée par l'étendue haut/bas sur la même période) ; MACD recadre son échelle en continu sur ce qui est visible (même logique que `YAutoScaling` pour le prix), et se dessine en histogramme (vert/rouge) + ligne MACD + ligne de signal. **Chaque panneau (volume compris) se redimensionne** en glissant le fin liseré juste au-dessus de son en-tête — un `Record<string, number>` interne retient la hauteur (en fraction de la hauteur du tracé) par panneau, clé "volume" ou l'id de l'indicateur ; le tracé des prix reçoit toujours ce qu'il reste. La modale "Ajouter un indicateur" a été retravaillée pour rester utilisable à mesure que la liste s'allonge : barre de recherche (filtre sur le nom), entrées groupées par catégorie ("Moyennes mobiles", "Volatilité", "Momentum") avec un intitulé de groupe, lignes plates sans bordure individuelle (fond au survol seulement) — et **"Volume" y apparaît aussi** (si `showVolume`), à côté des indicateurs, pour re-afficher le panneau volume s'il a été réduit ou supprimé, plutôt que de rester une bascule uniquement accessible depuis le bouton "Supprimer" de son propre en-tête. Les 25px d'espace entre les icônes du panneau et l'axe des prix ne prenaient initialement aucun effet : sa largeur est fixée en px par style inline (`dims.boundedWidth`) sans `box-sizing: border-box`, donc en `content-box` (par défaut) le padding s'ajoutait *en plus* de cette largeur au lieu d'y mordre — la zone de contenu (et tout ce qui s'y ancre via `justify-content: space-between`) ne bougeait donc jamais, quel que soit le padding. `border-box` corrige ça. `box-sizing: border-box` est maintenant posé globalement sur tout élément sous `.lq-root` (dans `tokens.css`, aux côtés des autres styles globaux comme les scrollbars) plutôt qu'au cas par cas comme ci-dessus : le même bug (`width: 100%` + padding/bordure qui déborde de son conteneur au lieu que le padding y morde dedans) touchait aussi le champ date de la modale d'édition des lignes, la faisant déborder horizontalement (scrollbar visible en bas de la modale).
- `DeltaChart` — graphique en cascade (waterfall/bridge) : ajouts/retraits signés qui construisent un ou plusieurs totaux, avec connecteurs pointillés (ex. structure du capital : capitalisation + dette + intérêts minoritaires − trésorerie = valeur d'entreprise) ; zoom + pan + rescale par axe comme les autres graphiques. Les barres apparaissent avec une animation de croissance échelonnée au chargement (désactivée en palette e-ink / `prefers-reduced-motion`)
- `GaugeChart` — jauge en arc avec bandes de seuils (ex. score de risque)
- `DonutChart` — répartition (allocation de portefeuille…)
- `Sparkline` — mini-courbe sans axes, pour cellule de tableau ou StatCard
- `ChartTooltip`, `ChartAxis` — primitives exposées si tu construis ton propre graphique par-dessus

**Forms** — dropdowns adaptatifs (collision detection), champs avec état d'erreur
- `Popover` — moteur de positionnement générique (flip vertical bas/haut + décalage horizontal gauche/droite selon l'espace dispo), portalé dans `document.body` **avec réapplication du thème actif** (palette/surface/police) sur le portail, donc stylé correctement même en dehors de l'arbre `.lq-root` ; ferme au clic extérieur/Échap
- `Select` — dropdown construit sur `Popover`
- `TextField` — champ texte de base (label, icônes, erreur, texte d'aide)
- `MaskedInput` — moteur de masque générique (`#` = chiffre, tout le reste est littéral), caractère de masque configurable (`maskChar`)
- `PhoneInput`, `CreditCardInput`, `DateInput` — masques prêts à l'emploi construits sur `MaskedInput`
- `NumberField` — champ numérique avec préfixe/suffixe (€, %) et steppers
- `PasswordField` — champ mot de passe avec bascule afficher/masquer
- `DatePicker` — calendrier en popup (même moteur de positionnement que `Select`). Cliquer sur le libellé "mois année" fait remonter vers une grille de mois, puis une grille d'années (± décennie) — beaucoup plus rapide que de paginer mois par mois pour changer d'année
- `DateRangePicker` — même calendrier, pour choisir une plage (date A → date B, comme une réservation) : 1er clic = début, survol = aperçu de la plage jusqu'au curseur, 2ème clic = fin (inversée automatiquement si elle précède le début) ; `value`/`onChange` prennent `{ start, end }`
- `DateTimePicker` — même calendrier + un panneau heure à droite, composant à part entière (le `DatePicker` sans heure reste inchangé) : une liste déroulante par pas de `minuteStep` (défaut 15 min, à scroller/cliquer) plus un champ texte au-dessus pour taper une heure précise hors grille (ex. "9h07", Entrée ou clic ailleurs pour valider) ; choisir un jour ne ferme pas le popup, le bouton "Valider" confirme date + heure
- `RangeSlider` — double curseur (plage de prix, de dates…) ; glisser le segment central pour décaler toute la plage sans changer sa largeur ; `centerZero` pour une plage bipolaire (négatif à gauche, positif à droite, avec repère au 0)
- `Dropzone` — zone de dépôt de fichiers (drag & drop + sélection au clic), liste de fichiers avec suppression, validation de taille
- `Checkbox` — case à cocher avec coche animée au tracé (SVG `stroke-dashoffset`), état indéterminé pour les groupes
- `CheckboxButton` — case à cocher qui a l'apparence d'un `Button` : coché → ton actif + icône coché animée, décoché → bouton neutre, sans icône (filtres sous forme de puces)
- `Tag` — puce supprimable (croix optionnelle)
- `TagInput` — saisie de tags libres : virgule/Entrée pour ajouter, Retour arrière (champ vide) ou croix pour retirer

**Feedback**

**Finance** — composants pensés pour un dashboard finance, mais génériques
- `Badge` — pastille de statut (tons neutral/up/down/warning/info)
- `PriceChangeTag` — delta signé avec flèche (variation de cours, P&L)
- `StatCard` — tuile KPI (label, valeur, delta, sparkline)
- `HoldingCard` — carte compacte pour une position (watchlist, liste de titres)
- `ComparisonCard` — deux chiffres côte à côte avec séparateur (portefeuille vs. indice, période vs. période)
- `GaugeCard` — `GaugeChart` dans une carte titrée avec description

- `Breadcrumbs` — fil d'ariane

**Finance Widgets** — blocs composites directement utilisables dans un dashboard

## Développement

```bash
npm install
npm run storybook   # bac à sable visuel avec toolbar Palette / Surface / Typo
npm run typecheck
npm run build        # build de la lib (dist/) — types + ESM + CJS + CSS
```

Chaque story a un onglet **Docs** généré automatiquement (`@storybook/addon-docs`, `tags: ["autodocs"]` dans `.storybook/preview.tsx`) avec un bouton **Show code** sous le rendu — le JSX exact de la story, prêt à copier-coller. `Foundations/Icons` liste tous les icônes exportés par le kit (générés depuis les exports du module, pas une liste à maintenir à la main) ; `Foundations/Animated Icons` détaille en plus le comparatif statique/`animated` des icônes météo.

## Publication

```bash
npm version <patch|minor|major>
git push --follow-tags
```
